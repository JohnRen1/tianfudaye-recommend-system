# PRD：AI 财税体检与私域转化平台产品需求文档

## 1. 文档信息

| 项目   | 内容                                 |
| ---- | ---------------------------------- |
| 产品名称 | AI 财税体检与私域转化平台                     |
| 产品版本 | MVP v1.0                           |
| 产品形态 | H5 / 微信小程序 + Web 管理后台              |
| 目标用户 | 沙龙听课用户、企业老板、财务负责人、税务顾问、市场运营人员、管理者  |

---

## 2. 产品目标

### 2.1 业务目标

1. 将沙龙听课用户沉淀为线上注册用户。
2. 通过资料领取、AI 问答、风险测评提升用户黏度。
3. 通过手机号、企业信息、预约表单获取销售线索。
4. 通过线索评分识别高意向用户。
5. 通过顾问后台提高跟进效率。
6. 通过活动数据看板评估沙龙活动效果。

### 2.2 用户目标

1. 用户可以方便领取沙龙资料。
2. 用户可以通过 AI 咨询基础税务问题。
3. 用户可以完成企业财税风险测评。
4. 用户可以获得初步风险报告。
5. 用户可以预约人工顾问进一步咨询。

### 2.3 产品目标

MVP 阶段重点跑通以下闭环：

**活动二维码 → 活动页 → 资料领取 → 注册留资 → AI 问答 → 风险测评 → 风险报告 → 预约顾问 → 线索后台 → 顾问跟进**

## 5. 核心业务流程

## 5.1 沙龙现场扫码流程

```text
用户参加沙龙
→ 扫描活动二维码
→ 进入活动落地页
→ 查看课程介绍和资料领取入口
→ 手机号 / 微信授权登录
→ 领取资料
→ 引导使用 AI 税务助手或风险测评
→ 系统记录用户来源和行为
```

### 关键要求

1. 每个活动二维码必须绑定活动 ID。
2. 用户扫码后自动记录来源。
3. 用户注册后自动打上活动标签。
4. 用户领取资料后生成资料领取记录。
5. 页面需要突出 AI 问答和风险测评入口。

---

## 5.2 AI 问答流程

```text
用户进入 AI 税务助手
→ 输入税务问题
→ 系统识别问题类型
→ RAG 检索知识库
→ 大模型生成回答
→ 展示风险提示和建议
→ 必要时引导预约顾问
→ 系统记录问题、回答、标签、风险等级
```

### 关键要求

1. AI 回答必须基于知识库优先。
2. 对高风险问题必须提示人工顾问介入。
3. 回答不得提供违法避税建议。
4. 回答需包含免责声明。
5. 问答记录需要进入后台，供顾问查看。

---

## 5.3 风险测评流程

```text
用户进入风险测评
→ 回答企业基础信息
→ 回答风险问卷
→ 系统计算风险分
→ AI 生成风险报告
→ 展示基础报告
→ 引导用户留资查看完整报告
→ 高风险用户进入线索池
```

### 关键要求

1. 测评问题需要结构化。
2. 风险分计算采用规则引擎。
3. 大模型只负责解释和生成报告，不直接决定风险分。
4. 高风险报告必须提示预约顾问。
5. 报告需要可在用户中心查看。

---

## 5.4 顾问跟进流程

```text
用户完成测评 / 预约 / 高风险提问
→ 系统生成线索
→ 线索评分 Agent 计算意向分
→ 高意向线索进入顾问待跟进列表
→ 顾问查看用户画像和问题摘要
→ 顾问联系用户
→ 顾问填写跟进记录
→ 更新线索状态
```

### 关键要求

1. 线索需要展示来源活动。
2. 线索需要展示用户标签。
3. 线索需要展示 AI 问答和测评结果。
4. 顾问可以更新跟进状态。
5. 管理者可以查看顾问跟进效果。

## 6.2 用户登录 / 注册

### 功能说明

用于获取用户基础身份，沉淀私域用户。

### 登录方式

MVP 支持：

1. 手机号验证码登录。
2. 微信授权登录。

### 注册字段

第一阶段必填：

* 手机号
* 微信 openid
* 来源活动 ID
* 来源二维码 ID

第二阶段引导补充：

* 姓名
* 身份：老板 / 财务 / 会计 / 创业者 / 其他

* 所属行业
* 企业规模

### 业务规则

1. 用户首次登录自动创建用户档案。
2. 同一手机号视为同一用户。
3. 同一微信 openid 视为同一用户。
4. 用户来源以首次进入来源为主，同时记录历史来源。
5. 用户未补充企业信息时，不影响基础功能使用。

### 验收标准

1. 用户可以通过手机号登录。
2. 用户可以通过微信授权登录。
3. 登录后能领取资料、提问、测评。

## 6.4 AI 税务助手

### 功能说明

为用户提供基于公司知识库的税务问答服务。

### 输入

* 用户自然语言问题
* 用户身份
* 企业行业
* 历史提问
* 当前活动来源

### 输出结构

AI 回答建议统一为：

1. 问题理解
2. 初步判断
3. 涉及风险
4. 处理建议
5. 是否建议人工顾问介入
6. 免责声明

### 示例回答结构

```text
你的问题可能涉及发票合规和企业所得税税前扣除。

初步判断：
如果业务真实、合同、付款、发票、物流或服务记录完整，风险相对可控。
如果只有发票但缺少真实业务支撑，可能存在较高风险。

风险等级：中高

建议：
1. 核查业务真实性材料。
2. 检查合同、付款记录、验收记录是否完整。
3. 如金额较大，建议由顾问进一步判断。

提示：
以上内容仅供参考，不构成正式税务意见。
```

### 风险问题识别

以下问题应触发高风险提醒：

1. 公转私金额较大。
2. 被税务局约谈。
3. 收到税务检查通知。
4. 虚开发票。
5. 买票、卖票。
6. 隐匿收入。
7. 长期零申报。
8. 大额无票支出。
9. 个税社保长期异常。
10. 历史补税或罚款。

### 业务规则

1. AI 不得输出违法避税方案。
2. AI 不得承诺节税结果。
3. AI 不得替代正式税务意见。
4. 高风险问题需要引导预约顾问。
5. 问答记录需要保存。
6. 用户提问可生成标签。
7. 免费用户可限制每日提问次数，MVP 可先不限制。

### 验收标准

1. 用户可以正常发起税务问题。
2. 系统可以返回结构化回答。
3. 高风险问题能触发转人工提示。
4. 后台能查看用户问答记录。
5. 回答中包含免责声明。
6. AI 回答不出现明显违规引导。

## 6.5 企业财税风险测评

### 功能说明

通过问卷方式收集企业情况，生成风险评分和初步报告。

### 测评维度

1. 企业基础信息
2. 发票合规风险
3. 公转私风险
4. 企业所得税风险
5. 增值税风险
6. 个税社保风险
7. 成本费用风险
8. 长期零申报风险
9. 税负率异常风险
10. 税务稽查应对风险

### 基础问题示例

#### 企业基础信息

1. 企业所属行业是什么？
2. 企业年营业收入区间是多少？
3. 企业员工人数是多少？
4. 企业纳税人类型是什么？
5. 是否有专职财务人员？

#### 发票风险

1. 是否存在大额无票支出？
2. 是否存在供应商无法提供合规发票？
3. 是否存在发票与实际业务不一致？
4. 是否存在集中开票或异常开票情况？

#### 公转私风险

1. 是否存在频繁公户转个人账户？
2. 公转私用途是否有完整凭证？
3. 是否存在老板个人账户收款？
4. 是否存在员工代收代付？

#### 个税社保风险

1. 是否所有员工依法缴纳社保？
2. 是否存在工资拆分发放？
3. 是否存在劳务人员长期固定办公？
4. 是否存在个人报销金额异常？

### 风险评分规则

建议采用 100 分制：

| 风险等级 |   分数区间 | 说明        |
| ---- | -----: | --------- |
| 低风险  |   0-30 | 暂未发现明显风险  |
| 中风险  |  31-60 | 存在部分不规范事项 |
| 高风险  |  61-80 | 存在较明显税务风险 |
| 严重风险 | 81-100 | 建议尽快由顾问介入 |

### 报告内容

1. 总体风险等级
2. 风险分数
3. 主要风险模块
4. 每个模块的风险说明
5. 初步整改建议
6. 顾问解读建议
7. 免责声明

### 留资设计

1. 完成测评后可免费查看基础结果。
2. 查看完整报告需要手机号。
3. 申请顾问解读需要填写企业名称和联系方式。
4. 高风险用户自动进入线索池。

### 验收标准

1. 用户可以完成测评。
2. 系统可以计算风险分数。
3. 系统可以生成基础报告。
4. 用户留资后可以查看完整报告。
5. 高风险用户能自动生成线索。
6. 后台可以查看测评答案和报告。

## 8. AI Agent 需求

## 8.1 RAG 税务问答 Agent

### 目标

基于知识库回答用户税务问题。

### 输入

* 用户问题
* 用户基础信息
* 历史问答
* 知识库检索结果

### 输出

* 结构化回答
* 风险等级
* 建议动作
* 是否转人工
* 免责声明

### 约束

1. 优先基于知识库回答。
2. 不确定时说明不确定。
3. 高风险问题建议人工咨询。
4. 不提供违法违规建议。
5. 不承诺节税效果。

---

## 8.2 风险测评报告 Agent

### 目标

根据规则评分结果生成自然语言报告。

### 输入

* 测评答案
* 风险分数
* 风险等级
* 风险模块

### 输出

* 总体风险说明
* 各模块风险解释
* 初步整改建议
* 顾问介入建议

### 约束

1. 风险等级由规则系统决定。
2. 大模型只负责解释。
3. 高风险报告必须包含人工顾问建议。
4. 不输出正式税务结论。

---

## 8.3 用户标签 Agent

### 目标

根据用户行为生成标签。

### 标签类型

1. 身份标签：老板、财务、创业者。
2. 来源标签：某场沙龙、某顾问、某渠道。
3. 需求标签：发票风险、公转私、个税社保、稽查应对。
4. 意向标签：低意向、中意向、高意向。
5. 风险标签：低风险、中风险、高风险。

### 验收标准

1. 用户提问后可生成问题标签。
2. 完成测评后可生成风险标签。
3. 后台用户详情可展示标签。

3. 顾问后台可以看到推荐跟进理由。

## 11. 非功能需求

## 11.1 合规需求

1. AI 回答必须展示免责声明。
2. 不得承诺节税结果。
3. 不得引导违法避税。
4. 高风险问题必须提示人工顾问。
5. 用户隐私数据需要明确授权。

## 11.2 安全需求

1. 用户手机号加密存储或脱敏展示。
2. 后台账号需要登录认证。
3. 不同角色权限隔离。
4. 操作日志可追溯。
5. 文件下载链接需要防止泄露。

## 11.3 性能需求

1. 活动页打开时间不超过 3 秒。
2. AI 问答平均响应时间建议控制在 10 秒以内。
3. 风险测评报告生成建议控制在 15 秒以内。
4. 后台列表查询支持分页。

## 11.4 可维护性需求

1. 知识库支持更新。
2. 测评题目支持后台配置。
3. 风险规则支持后续调整。
4. 活动页内容可配置。
5. 二维码来源可追踪。

## 16. 风险控制规则

### 16.1 AI 回答边界

AI 不允许输出以下内容：

1. 指导用户虚开发票。
2. 指导用户隐匿收入。
3. 指导用户伪造合同或凭证。
4. 指导用户通过违法方式避税。
5. 承诺一定可以节税。
6. 承诺一定不会被查。
7. 代替税务师给出最终法律或税务意见。

### 16.2 高风险转人工规则

以下场景必须转人工：

1. 用户已收到税务检查或稽查通知。
2. 用户涉及大额补税或罚款。
3. 用户提到虚开发票。
4. 用户提到买票、卖票。
5. 用户提到隐匿收入。
6. 用户存在大额公转私。
7. 用户涉及历史违法违规行为。
8. 用户需要具体税务筹划方案。

### 16.3 免责声明

建议所有 AI 回答底部统一展示：

```text
以上内容由 AI 根据现有知识库生成，仅供参考，不构成正式税务意见。具体处理方案需结合企业实际情况，并由专业税务顾问进一步确认。
```

## 18. PRD 总结

本产品 MVP 的核心不是做一个复杂财税系统，而是优先跑通税务咨询公司的业务闭环：

**沙龙扫码获客 → 资料领取留资 → AI 税务问答提升黏度 → 风险测评识别需求 → 顾问跟进完成转化 → 活动数据复盘优化获客。**

第一版应坚持轻量化、转化导向和 AI 赋能三个原则：

1. 轻量化：用户扫码即用，降低进入门槛。
2. 转化导向：每个功能都服务于留资、识别需求和预约顾问。
3. AI 赋能：用 RAG、Agent、风险测评和顾问辅助提升专业服务效率。

## 20. 关键交互逻辑

### 20.1 用户端主流程

```text
用户参加沙龙
→ 扫描活动二维码
→ 系统识别活动 ID 和二维码 ID
→ 进入活动落地页
→ 点击领取资料 / AI 税务助手 / 风险测评 / 预约顾问
→ 触发登录或直接进入功能
→ 系统记录用户来源和行为
→ 根据用户行为生成标签和线索分
→ 高风险或高意向用户进入线索池
→ 顾问后台跟进
```

关键规则：

1. 活动二维码必须绑定活动 ID，扫码后自动记录来源活动和来源二维码。
2. 用户首次注册后，来源活动以首次进入来源为主，同时保留历史来源记录。
3. 用户端所有关键转化动作均需埋点，包括资料领取、AI 提问、测评完成、报告查看和预约顾问。
4. AI 高风险问题、严重风险报告、提交预约顾问均应触发线索生成或线索评分更新。

### 20.2 登录拦截逻辑

触发登录拦截的操作：

1. 领取或下载资料。
2. 查看完整风险报告。
3. 提交预约顾问。
4. 查看用户中心历史记录。
5. 补充或修改企业信息。

处理逻辑：

```text
用户点击受限操作
→ 系统判断是否已登录
→ 未登录则弹出登录弹窗或跳转登录页
→ 用户完成手机号 / 微信授权登录
→ 系统创建或更新用户档案
→ 返回原页面
→ 继续执行原操作或提示用户继续操作
```

业务规则：

1. 未登录用户可浏览活动页、基础资料说明、AI 助手介绍和测评入口。
2. 登录后可领取资料、提问、测评、查看报告和提交预约。
3. 首次登录不强制补充企业信息，但可在资料领取、完整报告和预约顾问场景中引导补充。

### 20.3 资料领取逻辑

```text
用户进入活动页或资料页
→ 系统根据活动 ID 加载关联资料
→ 用户点击领取资料
→ 判断是否需要登录
→ 判断是否需要补充企业信息
→ 满足条件后生成资料领取记录
→ 更新按钮状态为已领取 / 可下载
→ 增加用户线索分和资料领取埋点
```

业务规则：

1. 资料可绑定活动，也可作为通用资料展示。
2. 资料可配置是否需要登录、是否需要补充企业信息。
3. 用户领取资料后，后台需记录资料 ID、用户 ID、活动 ID、二维码 ID、领取时间。
4. 多次领取同一资料不重复生成多条有效领取记录，但可记录访问或下载次数。

### 20.4 AI 问答交互逻辑

```text
用户进入 AI 税务助手
→ 输入税务问题
→ 系统显示 AI 生成中状态
→ 系统识别问题类型和风险关键词
→ RAG 检索知识库
→ 大模型生成结构化回答
→ 系统判断风险等级和是否建议转人工
→ 前端展示回答、风险标签、处理建议和免责声明
→ 后台保存问答记录
→ 命中高风险时增加线索分或生成线索
```

AI 回答展示结构：

1. 问题理解。
2. 初步判断。
3. 涉及风险。
4. 处理建议。
5. 风险等级。
6. 是否建议人工顾问介入。
7. 免责声明。

高风险处理规则：

1. 命中虚开发票、买票卖票、隐匿收入、税务检查、大额公转私、历史补税罚款等场景时，必须展示高风险提醒。
2. 高风险回答下方必须展示“预约顾问”入口。
3. 后台问答记录字段 `need_human` 标记为 true。
4. 系统应为用户增加线索分；达到阈值时自动进入线索池。

### 20.5 风险测评与报告逻辑

```text
用户进入风险测评
→ 阅读测评说明
→ 填写企业基础信息
→ 回答各风险维度问题
→ 系统校验必填题
→ 用户提交测评
→ 规则引擎计算风险分
→ 系统判定风险等级
→ 报告 Agent 生成自然语言报告
→ 用户查看基础报告
→ 登录 / 留资后查看完整报告
→ 高风险用户进入线索池
→ 报告保存到用户中心
```

风险分规则：

| 风险等级 | 分数区间 | 页面表现 |
| --- | ---: | --- |
| 低风险 | 0-30 | 绿色标签，提示暂未发现明显风险 |
| 中风险 | 31-60 | 黄色标签，提示存在部分不规范事项 |
| 高风险 | 61-80 | 橙色标签，突出预约顾问入口 |
| 严重风险 | 81-100 | 红色标签，强提示尽快顾问介入 |

报告解锁规则：

1. 基础报告免费展示，包括总体风险等级、风险分数、主要风险模块和简短建议。
2. 完整报告需登录并留手机号后查看。
3. 完整报告可展示模块详细说明、整改建议和顾问解读建议。
4. 解锁完整报告行为应增加线索分。

### 20.6 预约顾问逻辑

```text
用户进入预约顾问页
→ 填写姓名、手机号、咨询主题、问题描述
→ 可选填写企业名称、行业、联系时间、微信号
→ 系统校验必填项
→ 提交预约
→ 系统生成线索
→ 线索状态默认为待跟进
→ 后台顾问或管理员查看并处理
```

业务规则：

1. 预约顾问必须生成线索。
2. 线索需关联用户、来源活动、来源二维码、预约主题和问题描述。
3. 提交成功后用户端显示成功提示，并提供“返回首页”“查看我的预约”“继续问 AI”等入口。
4. MVP 阶段内部通知可先通过后台提醒实现。

### 20.7 后台线索跟进逻辑

```text
系统生成线索
→ 线索评分 Agent 计算意向分
→ 线索进入线索管理列表
→ 管理员或运营人员分配顾问
→ 顾问查看线索详情
→ 顾问添加跟进记录
→ 顾问更新线索状态
→ 管理者查看跟进效率和转化结果
```

线索状态流转建议：

```text
新线索 → 待跟进 → 已分配 → 跟进中 → 已预约 → 已成交
                                    ↘ 无效线索
```

顾问详情页应重点展示：

1. 用户来源活动和二维码。
2. 用户身份、企业信息和标签。
3. AI 问答摘要。
4. 风险测评摘要。
5. 意向分构成。
6. 推荐沟通重点。
7. 历史跟进记录。

## 21. 页面状态与异常状态

### 21.1 通用状态

| 状态 | 说明 | 处理方式 |
| --- | --- | --- |
| 加载中 | 页面数据、列表数据或报告正在请求 | 展示骨架屏、加载动画或进度提示 |
| 空状态 | 当前无资料、无报告、无问答、无线索等 | 展示空状态说明和下一步引导按钮 |
| 未登录 | 用户尚未完成登录 | 展示登录引导或登录弹窗 |
| 网络异常 | 接口请求失败或网络不可用 | 展示错误提示和重试按钮 |
| 权限不足 | 后台用户无权限访问相关数据 | 展示权限不足说明，不展示敏感数据 |
| 操作成功 | 领取、保存、提交、分配等操作成功 | Toast、成功弹窗或成功页反馈 |
| 操作失败 | 表单校验失败、接口失败或业务规则不满足 | 明确提示失败原因，并支持重新操作 |
| 数据刷新 | 看板、列表或详情数据更新中 | 保留当前数据并显示刷新状态 |

### 21.2 用户端页面状态

| 页面 | 状态 | 展示内容 / 处理方式 |
| --- | --- | --- |
| 活动落地页 | 无效二维码 | 展示默认落地页，保留资料、AI 和测评入口 |

## 22. UI 设计原则

### 22.1 用户端设计原则

1. **轻量化**：用户扫码进入后应快速看到活动信息、资料领取和核心服务入口，避免复杂路径。
2. **转化导向**：资料领取、AI 问答、风险测评、完整报告和预约顾问应形成连续转化链路。
3. **专业可信**：界面文案应克制、专业、合规，避免夸张承诺和恐吓式表达。
4. **风险提示清晰**：高风险问题和严重风险报告需要醒目提示，但不得制造不必要恐慌。
5. **移动端优先**：按钮、表单、测评选项应适配微信小程序触控操作，点击区域足够清晰。
6. **隐私友好**：涉及手机号、企业信息、问答内容、测评结果时，应展示必要的授权和隐私说明。
7. **AI 边界明确**：所有 AI 回答和风险报告必须展示免责声明，不得暗示其为正式税务意见。

### 22.2 后台设计原则

1. **数据优先**：首页优先展示活动转化、线索增长、AI 使用、测评完成和顾问跟进指标。
2. **线索优先**：高意向线索、高风险线索和待跟进线索应在列表和看板中突出显示。
3. **顾问高效**：用户详情和线索详情应帮助顾问快速理解用户来源、关注问题、风险摘要和推荐沟通重点。
4. **权限清晰**：不同角色只展示其权限范围内的数据和操作，敏感字段需脱敏。
5. **操作可追溯**：活动上下架、资料删除、线索分配、跟进状态更新、知识库停用等关键操作应记录日志。
6. **筛选高效**：用户、问答、报告和线索列表应支持按活动、渠道、风险等级、意向等级、顾问和时间筛选。
7. **状态明确**：活动、二维码、资料、线索、知识库均需有明确状态标签，减少运营误操作。

### 22.3 视觉方向建议

1. 主色建议使用专业蓝，体现稳定、专业和可信。
2. 强调色建议使用金色或橙色，用于资料领取、开始测评、预约顾问等关键 CTA。
3. 风险色建议保持统一：低风险绿色、中风险黄色、高风险橙色、严重风险红色。
4. 用户端采用卡片式、轻量化布局；后台采用 SaaS 风格的左侧导航、顶部筛选、表格和详情抽屉布局。
5. 数据看板应使用指标卡、漏斗图、趋势图和排行表呈现关键转化数据。

## 23. v0.app 原型生成建议

为提升 v0.app 生成质量，建议将设计提示词按模块分批输入，而不是一次性生成全部页面。

### 23.1 推荐生成顺序

1. 用户端小程序核心页面：活动落地页、AI 税务助手、风险测评、风险报告、预约顾问、用户中心。
2. 后台基础框架：首页看板、左侧导航、活动管理、资料管理、线索管理。
3. 后台详情页面：用户详情、线索详情、问答详情、测评报告详情。
4. 页面状态补充：未登录、加载中、空状态、高风险提醒、完整报告未解锁、预约成功、分配顾问、添加跟进记录。

### 23.2 v0.app 生成原则

1. 提示词中需明确产品背景、用户角色、页面目标、核心内容、主要交互和视觉风格。
2. 移动端页面按微信小程序风格设计，但可先生成 H5 / React 原型用于评审。
3. 后台页面按现代 SaaS 管理后台风格设计，重点保证表格、筛选、详情抽屉和状态标签完整。
4. 生成结果应优先用于产品评审和研发理解，最终实现仍需结合小程序和后台技术栈调整。
