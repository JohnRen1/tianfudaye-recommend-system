## 二、设计原则与审计总纲对应

| 审计问题 | 对应决策 | 契约体现位置 |
|----------|----------|-------------|
| **S1** — `report.user` 用姓名字符串关联用户 | `userId` 外键（替代姓名字符串），`userName` 由服务端 join 返回 | `AssessmentReportListItemDTO` |
| **S4** — 题库 8 模块 vs 报告 5 模块不一致 | `AssessmentModuleKey`（8 个题库模块）与 `ReportModuleKey`（5 个报告展示维度）分开定义 | `assessment.ts` 枚举 |
| **S4** — `modules` 字段仅为 `string[]`，不含分数 | `ModuleScoreDTO` 结构化，含 `score` / `riskLevel` / `desc` / `advice` | `ModuleScoreDTO` |
| **S4** — `answers` 字段存自然语言字符串 | 拆分为 `rawAnswers`（索引数组）和 `summaryPoints`（自然语言摘要） | `RawAnswerDTO`、`AnswerSummaryPointDTO` |
| **S5** — 落地页选项含 `score` 权重，用户可逆向推算高分路径 | 落地页 `QuestionOptionPublicDTO` 故意省略 `score`；答题只提交选项索引，服务端计算分数 | `QuestionOptionPublicDTO`、`AssessmentSubmitDTO` |
| **S5** — 报告页从 URL `?score=` 读取分数 | 报告页通过 `reportId` 从服务端获取报告，不接受 URL 参数传入分数 | `AssessmentSubmitResponseDTO`、报告 API 路径设计 |
| **S5** — 解锁 / 保存状态仅存前端 state | `POST /api/assessment/report/:id/unlock` 和 `POST /api/assessment/report/:id/save` 落库 | `UnlockReportResponseDTO`、`SaveReportResponseDTO` |

|--------|----------|------|

## 八、安全约束说明（S5）

1. **题目 score 权重不暴露给落地页**：`GET /api/assessment/questions` 返回 `QuestionOptionPublicDTO`，故意省略 `score` 字段，防止用户逆向推算高分路径。
2. **报告分数服务端计算**：提交答题时前端只传选项索引数组（`selectedIndexes`），不传 `score`。服务端从题库读取权重后计算，结果落库后返回 `reportId`。
3. **报告页通过 reportId 获取报告**：落地页报告页必须通过 `GET /api/assessment/report/:id` 获取报告，不接受 URL `?score=` 参数（防止分数篡改）。
4. **解锁 / 保存状态后端落库**：`unlock` 和 `save` 操作各有独立 API 端点，状态变更落库后服务端返回最新报告状态，不依赖前端本地 state。
5. **未登录用户可做测评**：`POST /api/assessment/submit` 中 `userId` 可为 null，服务端生成匿名报告；用户登录后通过 `POST /api/assessment/report/:id/claim` 将报告绑定到账号。
