## 二、设计原则与审计总纲对应

| 审计问题 | 对应决策 | 契约体现位置 |
|----------|----------|-------------|
| **S1** — 资料用活动名称字符串关联 | `activityId` 外键，`activityName` 由服务端 join 返回 | `MaterialListItemDTO` |
| **S3** — 落地页领取资料只更新前端 state | `POST /api/material-claims` 落库；返回 `downloadUrl` | `MaterialClaimCreateDTO`、`MaterialClaimCreateResponseDTO` |
| **S4** — 资料状态字段混淆（上架状态 vs 领取状态同名） | `MaterialStatus`（上架状态）和 `MaterialClaimStatus`（领取状态）分开命名 | `material.ts` 枚举 |
| **S4** — `needsCompanyInfo` 命名不统一（多一个 s） | 统一为 `needCompanyInfo`（无 s） | `MaterialListItemDTO`、`MaterialCreateDTO` |
| **S4** — 文件格式 "XLSX" vs "Excel" 歧义 | 统一为 `FileFormat` 枚举（`pdf`/`xlsx`/`pptx`/`docx`），展示层映射 | `material.ts` 枚举 |
| **S4** — `id` 格式不一致（admin MAT-001 vs landing number） | 统一为 UUID `string` | `MaterialListItemDTO` |
| **S6** — 资料统计字段（领取趋势 / 用户画像）为硬编码数组 | `MaterialStatisticsDTO` 从后端聚合计算 | `MaterialStatisticsDTO` |

### 4.1 资料目录管理（admin-system）

| 方法 | 路径 | 认证 | 权限 | 描述 |
|------|------|------|------|------|

| 方法 | 路径 | 认证 | 描述 |

## 五、DTO 详情

### 5.1 MaterialListItemDTO

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `string` | UUID 主键（S4：废弃 MAT-001 格式） |
| `name` | `string` | 资料名称 |
| `type` | `MaterialType` | 资料类型枚举 |
| `subType` | `string \| null` | 细分类型标签（如"课程课件"），自由字符串 |
| `format` | `FileFormat` | 文件格式枚举 |
| `activityId` | `string \| null` | 关联活动外键（S1） |
| `activityName` | `string \| null` | 关联活动名称（服务端 join） |
| `needLogin` | `boolean` | 是否需要登录才能领取 |
| `needCompanyInfo` | `boolean` | 是否需要补充企业信息（S4：统一无 s） |
| `status` | `MaterialStatus` | 上架状态（S4：区别于领取状态） |
| `downloads` | `number` | 累计下载次数 |
| `createdAt` | `string` | ISO 8601 |

### 5.2 MaterialDetailDTO

继承 `MaterialListItemDTO` 全部字段，额外增加：

| 字段 | 类型 | 说明 |
|------|------|------|
| `fileUrl` | `string` | 文件存储 URL（预览 Dialog 用） |
| `fileSizeBytes` | `number \| null` | 文件大小（字节数，展示层格式化） |
| `description` | `string \| null` | 资料描述 |
| `updatedAt` | `string` | ISO 8601 |

### 5.3 MaterialCreateDTO

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `name` | `string` | 是 | 资料名称 |
| `type` | `MaterialType` | 是 | 资料类型 |
| `subType` | `string` | 否 | 细分标签 |
| `storageKey` | `string` | 是 | 文件存储 Key（客户端先上传文件得到） |
| `format` | `FileFormat` | 是 | 文件格式 |
| `fileSizeBytes` | `number` | 是 | 文件大小（字节数） |
| `activityId` | `string \| null` | 否 | 关联活动外键（S1） |
| `needLogin` | `boolean` | 是 | 是否需要登录 |
| `needCompanyInfo` | `boolean` | 是 | 是否需要补充企业信息 |
| `status` | `MaterialStatus` | 是 | 初始上架状态 |
| `description` | `string` | 否 | 资料描述 |

**服务端生成字段**：`id`、`createdAt`、`updatedAt`、`downloads`、`fileUrl`。

### 5.4 MaterialUpdateDTO

所有字段可选，PATCH 语义（只更新传入字段）。字段集与 `MaterialCreateDTO` 相同，新增：

| 字段 | 类型 | 说明 |
|------|------|------|
| `storageKey` | `string` | 替换文件时传新 storageKey（须同时传 format / fileSizeBytes） |
| `subType` | `string \| null` | null 表示清空细分标签 |

### 5.5 MaterialQueryDTO

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `page` | `number` | `1` | 页码 |
| `pageSize` | `number` | `20` | 每页条数，最大 100 |
| `name` | `string` | — | 资料名称模糊搜索 |
| `type` | `MaterialType` | — | 资料类型精确筛选 |
| `activityId` | `string` | — | 关联活动 id 精确筛选（S1） |
| `format` | `FileFormat` | — | 文件格式精确筛选 |
| `status` | `MaterialStatus` | — | 上架状态筛选 |
| `needsAuth` | `boolean` | — | true = 只看需要留资的资料 |
| `sortBy` | `createdAt \| downloads \| name` | `createdAt` | 排序字段 |
| `sortOrder` | `asc \| desc` | `desc` | 排序方向 |

### 5.6 MaterialSummaryDTO

列表页顶部 5 张统计卡片（所有值为 `number`）：

| 字段 | 计算方式 |
|------|---------|
| `total` | 资料总数 |
| `published` | 已上架资料数 |
| `totalClaims` | 累计领取次数（sum） |
| `totalDownloads` | 累计下载次数（sum） |
| `withAuthGate` | 需留资资料数（needLogin=true 或 needCompanyInfo=true） |

### 5.7 MaterialStatisticsDTO

单条资料领取数据（替代硬编码趋势数组）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `materialId` | `string` | 当前资料 id |
| `materialName` | `string` | 资料名称 |
| `claims` | `number` | 累计领取次数 |
| `downloads` | `number` | 累计下载次数 |
| `claimToDownloadRate` | `number` | 下载率（%，服务端计算，防止除零） |
| `hasAuthGate` | `boolean` | 是否有留资门槛 |
| `trend` | `MaterialClaimTrendItemDTO[]` | 近 N 天领取趋势（默认 7 天） |
| `userPortrait` | `MaterialUserPortraitDTO[]` | 领取用户身份画像 |
| `periodFrom` | `string` | 统计时间范围起始，ISO 8601 |
| `periodTo` | `string` | 统计时间范围截止，ISO 8601 |

### 5.8 MaterialClaimCreateDTO（落地页）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `materialId` | `string` | 是 | 要领取的资料 id |
| `activityId` | `string \| null` | 否 | 来源活动 id（S2 归因链） |

**服务端行为**：从 JWT 读取 `userId`，创建领取记录，返回 `downloadUrl`（signed URL）。

### 5.9 MaterialClaimCreateResponseDTO（落地页）

| 字段 | 类型 | 说明 |
|------|------|------|
| `claimId` | `string` | 领取记录 id（UUID） |
| `materialId` | `string` | 被领取的资料 id |
| `claimedAt` | `string` | ISO 8601 |
| `downloadUrl` | `string` | 文件下载链接（signed URL，有效期限时） |
| `downloadUrlExpiresAt` | `string` | 下载链接过期时间，ISO 8601 |

## 八、文件上传流程

1. 前端先调用 Supabase Storage 直传接口，获取 `storageKey`。
2. 前端携带 `storageKey` + 元数据调用 `POST /api/admin/materials`。
3. 服务端验证 `storageKey` 有效性后创建资料记录，返回 `MaterialDetailDTO`。
4. 预览 Dialog 调用 `GET /api/admin/materials/:id`，服务端返回 signed `fileUrl`（有效期由服务端控制）。
