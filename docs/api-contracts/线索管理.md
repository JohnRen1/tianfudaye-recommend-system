## 二、设计原则与审计总纲对应

| 审计问题 | 对应决策 | 契约体现位置 |
|----------|----------|-------------|
| **S1** — 用 `name` 字符串跨查 User / Report / QaRecord | `userId` / `activityId` / `qrCodeId` / `advisorId` 全部改外键 | `LeadListItemDTO`、`LeadDetailDTO`、`FollowUpRecordDTO` |
| **S3** — 线索详情行为路径使用全局 userTimeline | `LeadDetailDTO.timeline` 按 userId 过滤 | `LeadDetailDTO`、`LeadTimelineEventDTO` |
| **S4** — 意向分构成 4 项写死 | `LeadScoreBreakdownDTO` 按真实行为计算 | `LeadScoreBreakdownDTO`、`LeadScoreDimensionDTO` |
| **S4** — 下一步话术硬编码 | 从跟进记录 `FollowUpRecordDTO` 中读取 | `FollowUpRecordDTO` |
| **S4** — 顾问下拉写死 | `LeadFilterOptionsDTO.advisors` 动态从 AdminUser 表加载 | `LeadFilterOptionsDTO` |
| **S4** — 需求标签下拉写死 | `LeadFilterOptionsDTO.tags` 从已有 leads.tags 聚合 | `LeadFilterOptionsDTO` |
| **S5** — `id` 格式混用日期编码 | `id`（UUID）与 `serialNo`（展示编号 L{YYYYMMDD}{3位}）分离 | `LeadListItemDTO` |

| 字段 | 类型 | 必填 | 说明 |

| `topic` | `AppointmentTopic` | 是 | 咨询主题枚举 |
| `description` | `string` | 是 | 问题描述 |
| `company` | `string` | 否 | 企业名称 |
| `industry` | `string` | 否 | 行业 |
| `contactTime` | `string` | 否 | 方便联系时间（自由文本） |
| `sourceQrId` | `string` | 否 | 来源二维码 id（S2 归因） |
| `sourceActivityId` | `string` | 否 | 来源活动 id（S2 归因） |

**服务端行为**：
1. 从 JWT 读取 userId，关联到已有 Lead 或创建新 Lead。
2. 若线索 status 不是 `appointed` / `converted`，联动更新为 `appointed`。
3. 若用户尚无线索（leadStatus = `none`），先创建 Lead 再关联。

## 八、Lead 状态机

```
new ──► pending ──► assigned ──► following ──► appointed ──► converted
 │                      │            │              │
 └──────────────────────┴────────────┴──────────────┴──► invalid
```

**特殊联动**（预约提交时服务端处理）：
- 落地页 `POST /api/appointments` → 若线索 status 不是 `appointed` / `converted`，自动更新为 `appointed`
- 若用户尚无线索（`User.leadStatus = 'none'`），先创建 Lead（status = `appointed`），再创建 Appointment

**终态约束**：
- `converted` / `invalid` 不允许再转换到其他状态
- 只有 `manager` / `market_ops` 可标记 `invalid`
- 只有 `tax_advisor` / `manager` 可标记 `converted`
